本地 LoRA 0.6B 追平 API 基线，但只在覆盖到的表达上 任务边界

已做到
  • 严格集 340 条全新表达：LoRA 0.6B 85.3% vs DeepSeek-chat 84.1%（McNemar p=0.708）、Qwen-plus 84.4%（p=0.810），统计打平
  • 本地单条 p50 239.6 ms，DeepSeek-chat API 936 ms；规则基线只有 50.6%
  • 训练句式 106 → 266 组后，v2「大模型在新写法上更优」的结论作废
还差
  • 指代类表达（本报告期 / 上上季度）只有 43.8%：依赖「报告期」约定，是任务边界，不是数据量问题
  • 英文写法 72.7%，低于两个 API；未做超参搜索与多 seed，85.3% 只是下界
  • 模型 ∪ 规则 90.0% 是上界，级联所需的路由器未实现
  • 现场 DeepSeek 超时按进程边界只重建 8091 端口（现场记录，REPORT_V3 未收录 —）；D 盘不存在「DC 模型」工程
来源：D:/llm-finetune/REPORT_V3.md §4.1、§4.3、§5.3、§7

微调全量回归对照未闭环 未闭环

已做到

多框架对照：配对测量才有意义 方法

已测到
  • LangGraph +36.9 ms，显著；LlamaIndex +14.8 ms，显著
  • LangChain、AutoGen 的差异落在噪声内，不构成结论
  • 样本量与 CI：—（D 盘未找到该对照的归档文件，数字按作者提供）
怎么读
  • 框架不是越快越好：多出的毫秒换来的是状态管理与可观测性，要看任务需要
  • 必须同一批样本、同一台机器配对测量并做显著性检验，否则差异与噪声不可区分
  • 该对照不用于跨项目排名，只用于本项目内的选型
