一条结论的证据路径

双路召回 → 门禁 → 账本 → 报告。任何一环不通过，结论不进账本。

  1. 01双路召回BM25 词面 + 向量语义，各自出候选
  2. 02证据门禁术语必须命中原文；无来源即丢弃
  3. 03事实账本结论与引用绑定，可复算核对
  4. 04治理报告摘要、口径、拒绝项与未决事项
  1. STEP 1提问研究问题或方法选型
  2. STEP 2检索词面召回 + 向量召回，合并去重
  3. STEP 3裁决可复算检查给出一致 / 不一致 / 越界
  4. STEP 4交付证据摘要 + 口径说明 + 拒绝记录

混合检索：词面保术语，向量保语义 双路召回

已做到
  • BM25 / 词面召回与向量召回并行，各自出候选后合并去重
  • 术语级精确匹配作为硬条件：模型名称、指标全称、经典方法代号必须命中原文，否则候选不进账本
  • 词面路负责「名字不能错」，向量路负责「换一种说法也找得到」
边界
  • 两路召回率 / MRR 等检索指标：—（未在 D 盘归档，不在本页给数）
  • 向量路对缩写与别名的覆盖依赖词表维护；词表外的新术语只能靠词面路兜底
来源：项目设计口径（实测数字 —）

证据门禁 + 事实账本：模型输出不直接当结论 门禁

已做到
  • 模型产出只是候选；进入账本前必须带来源定位（文档、章节、页码）
  • 一致性由可复算检查裁决：结论中的数值、术语与原文比对，不一致即标红
  • 越界问题（评价、预测、资料外事实）直接拒绝，拒绝理由写入记录
边界
  • 检查覆盖「可复算」的部分：数字、名称、方向词；语义改写程度仍需人工复核
  • researchos_governance 套件 n=12，全绿只说明这 12 条通过，不构成泛化结论；P95：样本不足，INSUFFICIENT_SAMPLE_FOR_P95
来源：data/metrics.js · researchos_governance（12/12，mean 273.243 ms）· conventions.p95_gate
